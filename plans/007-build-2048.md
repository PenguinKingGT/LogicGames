## Why this matters

PUZZLE HOUSE currently has four games, but none is a fast score-chasing number
game. 2048 adds an immediately recognizable, short-session experience that
fits the collection's local-only architecture and requires no new runtime
dependency. The implementation must be a complete, deterministic, tested game
whose engine is independent of React and whose keyboard, pointer, and touch
controls behave consistently.

## Product and rules contract

- Route: `/games/2048`; menu title: `数字方阵`; English title: `2048`.
- Board: 4×4. A new round starts with two tiles. Each spawned tile is `2` with
  90% probability and `4` with 10% probability, placed uniformly in an empty
  cell using an injected random source.
- A move slides all tiles fully in one cardinal direction. Equal adjacent
  values merge once per move; a produced tile cannot merge again during the
  same move. Examples: `[2,2,2,2] -> [4,4,0,0]` and
  `[4,4,8,0] -> [8,8,0,0]` when moving left.
- The score increases by the value of every produced tile. Spawn exactly one
  new tile only after a move that changes the board. Invalid/no-op moves do not
  change score, history, animation state, or storage.
- Reaching 2048 opens a non-blocking one-time victory dialog with `继续挑战`
  and `重新开局`. Continuing permits larger tiles and never shows that victory
  dialog again for the same round.
- The game is over only when the board is full and no horizontal or vertical
  adjacent pair can merge. The loss dialog shows score and best score and
  offers `再来一局`.
- Provide one-step undo. Undo restores the board and score from immediately
  before the last valid move, removes the spawned tile, and can be used once;
  it does not restore the prior random-generator position. A subsequent valid
  move replaces undo history. Undo is disabled at round start and after use.
- Restart asks for confirmation only after at least one valid move. There are
  no difficulty levels, timed modes, accounts, online leaderboards, AI hints,
  ads, or server persistence.
- Persist active board, score, best score, victory acknowledgement, and undo
  snapshot under `2048:v1`. Validate every stored field; malformed, impossible,
  or wrong-version data falls back to a fresh round without throwing.

## Visual and interaction direction

Use a crisp “typesetter's number tray” rather than copying the familiar beige
2048 skin. The board should feel like a physical composing case: deep
blue-black frame, cool paper cells, cobalt low-value tiles, persimmon milestone
tiles, and oversized tabular numerals. Keep the rest of the route quiet.

- Tokens: `ink #17212B`, `frame #243447`, `paper #F3F5F4`, `cell #DCE2E3`,
  `cobalt #315C9B`, `persimmon #D96B43`. Derive high-tile shades from explicit
  CSS classes/data attributes; always meet readable text contrast.
- Typography: Geist Sans for controls/copy and Geist Mono with tabular numbers
  for score and tiles. Do not add a web-font or package.
- Layout: compact header, centered square board, then a short key/gesture hint.
  Desktop and mobile share the same hierarchy:

  ```text
  ┌ 数字方阵 ─── SCORE ─ BEST ─ [↶] [新游戏] [声音] [玩法] ┐
  │                                                       │
  │              ┌──── 4 × 4 NUMBER TRAY ────┐           │
  │              │   2      8      ·      4   │           │
  │              │   ·      4      2      ·   │           │
  │              └────────────────────────────┘           │
  │             方向键 / WASD / 滑动移动数字              │
  └───────────────────────────────────────────────────────┘
  ```
- Signature moment: each valid move shows tiles traveling from their previous
  coordinates, then merged tiles land with one restrained typographic “press”
  pulse. New tiles fade/scale in only after travel completes.
- Animation must not determine game truth. The reducer commits the complete
  next state atomically and exposes movement metadata/IDs for the view. Ignore
  new input during the 140–180 ms visual transition. Under
  `prefers-reduced-motion`, skip travel/pulse while preserving input lock for
  at most one animation frame.
- Keyboard: Arrow keys and WASD move when board focus is active; prevent page
  scrolling only for handled game keys. Buttons retain visible focus. Provide
  an instructional `aria-describedby`, a concise polite live region for score
  changes/merge/game-over, and do not announce all 16 cells after every move.
- Touch/pointer: detect one dominant-axis swipe starting inside the board,
  require at least 28 CSS pixels, reject taps/diagonal ambiguity, and use
  `touch-action: none` only on the board. Controls must be at least 44×44 px.
- Use a scoped game stylesheet, support 320 px width, safe-area insets, light
  and dark modes, and `prefers-reduced-motion`. No canvas and no external image
  assets are needed.
- Generate quiet Web Audio cues locally: slide, merge, milestone, loss, and
  button. Follow the existing exception-safe lazy AudioContext pattern; sound
  must never delay or reject a move.

The deliberate design risk is using cool editorial/industrial colors for a
casual puzzle. It remains approachable through large numerals, soft 12–16 px
corners, short motion, and plain Chinese labels; do not add gradients, glossy
effects, or decorative statistics cards.

## Steps

### Step 1: Define and test the deterministic domain engine

Create `src/games/2048/domain/types.ts`, `engine.ts`, and `engine.test.ts`.
Represent the board as a fixed-length readonly 16-cell value array; tile values
must be zero or powers of two. Define `Direction`, `Board`, `MoveResult`, spawn
metadata, movement/merge metadata with stable per-round tile IDs, and pure
functions for line collapse, whole-board moves, spawning, win detection, and
game-over detection. Accept random values as arguments or an injected function;
never call `Math.random` inside test-critical pure transformations.

Tests must cover all four directions, empty gaps, `[2,2,2,2]`, `[2,2,4,0]`,
`[4,4,8,8]`, no double merge, score delta, no-op detection, uniform empty-cell
selection boundaries, 90/10 value threshold, win, playable full board, terminal
full board, and input immutability.

**Verify**: `pnpm test --run src/games/2048/domain` → all domain tests pass.

### Step 2: Build the reducer and animation-safe round state

Create `src/games/2048/app/game-reducer.ts` and tests. State must contain the
board, score, best score, phase (`ready`, `playing`, `animating`, `won`,
`continued`, `lost`), round ID, move ID, one undo snapshot, and current motion
metadata. Actions should cover hydrate/new round, move, finish animation,
continue after 2048, undo, and restart. Reject stale `finish-animation` actions
by round/move ID and ignore movement while animating or terminal.

The move action must atomically compute slide/merge, score, best score, spawn,
undo snapshot, victory/loss flags, and motion metadata. Decide outcome after
the spawn. Do not use timers, DOM APIs, storage, or audio in the reducer.

**Verify**: `pnpm test --run src/games/2048/app/game-reducer.test.ts` → reducer
transition, no-op, undo, victory continuation, loss, and stale-event tests pass.

### Step 3: Add defensive persistence and local audio

Create `src/games/2048/persistence/storage.ts` and tests using key `2048:v1`.
Validate board length, allowed tile values, score/best-score integers,
phase-derived flags, unique IDs, and undo snapshot independently. Never trust
parsed JSON casts. A storage write failure is a silent optional-feature failure.

Create `src/games/2048/audio/sounds.ts`, `audio-manager.ts`, and tests following
Circle Cat's lazy, user-gesture-safe Web Audio structure. The manager must
support enable/disable, tolerate missing/suspended contexts, disconnect nodes,
and expose only the planned cue names. Do not add audio files or URLs.

**Verify**: `pnpm test --run src/games/2048/persistence src/games/2048/audio` →
round-trip, malformed-data, unavailable-storage, lazy-context, disabled, and
cue-shape tests pass.

### Step 4: Build the accessible responsive game UI

Create `App.tsx`, `GameHeader.tsx`, `TileBoard.tsx`, `Dialog.tsx`,
`HelpDialog.tsx`, `ResultDialog.tsx`, and `ConfirmDialog.tsx` under the 2048
namespace. Initialize/hydrate after mount to avoid server/client randomness
mismatch. Allow tests to inject random values and animation duration. Register
keyboard handlers only while the board/game owns focus; clean up global
listeners and animation timers on restart/unmount.

Render 16 background cells and tiles in a separate absolute layer keyed by
stable tile IDs. Use CSS transforms from metadata; never infer merges from DOM
positions. Pointer handlers must distinguish swipes from button interactions.
Persist after stable reducer transitions, but do not record duplicate results
from repeated renders. Confirm destructive restart only for an active round.

UI tests must cover initial two tiles, keyboard and WASD moves, swipe threshold
and dominant axis, no-op input, animation lock, merge score, one-step undo,
hydration, sound preference, restart confirmation, win/continue, loss, live
region copy, and timer/listener cleanup.

**Verify**: `pnpm test --run src/games/2048/app` → all interaction tests pass.

### Step 5: Apply the scoped visual system and motion

Create `src/games/2048/styles/2048.css` using the tokens and layout above.
Define explicit tile-level treatments through at least 2048 and a readable
fallback for larger values. Scale tile typography down at 5+ digits. Add dark
mode, safe-area spacing, focus-visible states, 320 px behavior, landscape-short
viewport behavior, and reduced-motion overrides. Portaled dialogs must share
tokens through `.game-2048-portal`.

Use transform/opacity-only tile travel where possible. Ensure 16-cell geometry
is derived from shared CSS custom properties so background cells and moving
tiles cannot drift apart at responsive sizes.

**Verify**: `pnpm lint && pnpm typecheck` → both exit 0.
